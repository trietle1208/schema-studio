# RecordEditor

The panel at the right of the grid that edits one record of the table in Data mode, or makes a new one. The grid stays in view beside it (at 1440px the data pane keeps about 430px, and its header, selection bar and toolbar wrap).

- Props: `table`, `tables` (every table, for foreign keys and related records), `data` (the rows of every table, by name), `record` (the row to edit; none, or `null`, makes a **new record**), `draft` (values the form opens with over the record's own, so it opens with unsaved changes; for a new record, a duplicate's values), `tab` (`form` | `json` | `related`), `width` / `onWidth`, `autoFocus` (focus the first column that can be edited: for F2 and Add record, not for a click on a row), `onSave(values)`, `onClose()`, `onDirty(dirty)`. `jsonText`, `validated`, `attempted`, `confirmDiscard`, `related` and `picking` / `pickQuery` set a state that otherwise needs a click, for previews.
- **The editor keeps its own draft.** Mount it with a `key` for the record, so that another record starts from its own values. `onSave` gets the values that were set, converted to what the column holds (a number typed in a number column is a number, empty is `NULL` except in a text column). A new record leaves out what the database fills in; `S.completeRecord(table, rows, values)` makes the row of it (the next number of a counter, `now()`, `NULL`). `onClose` is called once there is nothing to lose. `onDirty(dirty, changedColumns)` lets the host ask before it leaves the record itself (another row, another table), with the same dialog.
- **Header:** "Edit record" / "New record" (`heading`), under it the record in mono, `users · id = 101` (`S.recordLabel`; a new one is `users · new`), `SaveStatus` in its dirty state once something differs from what was opened, and a close button (Esc). Under it the tabs **Form**, **JSON** and **Related records** (the count is the rows they hold; with a new record the tab is disabled: "A new record has no related records yet.").
- **Width:** 520px, dragged between 480 and 720 by the hairline at its left edge, as the inspector is (`ResizeHandle`: `accent` 2px when pointed at or dragged, double click goes back to 520, the arrows move it 16px, Home and End go to the ends). It takes no room of its own.
- **Footer:** the number of problems in `removed` ("1 problem"), **Cancel** (Esc), then the one primary: **Save changes** (⌘S, ⌘⏎; disabled until something changed) or **Create record** (⌘⏎). With problems, Save and Create only mark them (and focus the first) instead of saving.
- **Closing with changes** (close button, Esc, Cancel) asks in a `ConfirmDialog`: `Discard changes to users · id = 101?` (for a new record `Discard the new record in "users"?`), "2 changed columns will be lost: name, avatar_url.", **Keep editing** and the `danger` **Discard changes**. Without changes it just closes. A broken JSON text counts as a change.

## Form

Each column gets a block of the form: the key glyph (`pk`, `fk`), the name in mono, a `modified` dot once it was changed, and under it its type line in `ink-3` mono: `BIGINT · Primary key`, `VARCHAR(255) · Unique · Required`, `TIMESTAMP · Required · Default now()`. Hovering or focusing the block shows a copy button for its value. Problems show under the control in a `Field` error and turn its border `removed`; in a new record they wait until the column was touched or Create record was pressed.

| Column | Control |
| --- | --- |
| Serial, identity, auto increment | Read-only with a lock and the hint "Generated by the database"; in a new record it is empty (`DEFAULT`) |
| `VARCHAR`, `CHAR`, numbers | `Input` in mono (a `DECIMAL(12,2)` shows two decimals) |
| `TEXT` | A textarea in mono, 3 rows, resizable |
| `BOOLEAN` | `Switch` with `true` / `false` |
| `TIMESTAMP`, `DATE`, `TIME` | Mono `Input` in the format SQL writes (`YYYY-MM-DD HH:mm:ss`) with a clock that opens the picker of the browser |
| `ENUM(...)`, or text called `status`, `*_state`, `stage` | `Select`; an enum offers its values, a status column what the table already holds in it (and its default) |
| `JSON`, `JSONB` | The JSON editor with highlighting, 120px, the line of an error marked |
| Foreign key to a table that has rows | A picker: `users.id = 101 · an@example.com`. It opens a search over the key and over what names a row (its email, name, title, sku, or the first text column); ↑ ↓ ⏎ choose, Esc closes only the picker |
| Nullable | The same control, and a **NULL** toggle beside it. A column that is `NULL` shows `NULL` in `ink-3` and typing replaces it; in a text column an empty input is an empty string, not `NULL` |

A column with a literal default (`'pending'`, `1`, `false`) starts a new record with it filled in. One with `now()` or another expression starts empty with the expression as its placeholder and is left to the database.

Problems, in the order they are checked (the first of a column is told):

| Problem | Message |
| --- | --- |
| Empty and `NOT NULL` | `Column "email" cannot be empty.` |
| Not a number, not whole, too many decimals | `Value must be a number.` · `Value must be a whole number.` · `Value has more than 2 decimal places.` |
| Not `true` or `false` | `Value must be true or false.` |
| Not a moment | `Invalid timestamp format.` (`date`, `time`) |
| Not one of an `ENUM` | `Value must be one of pending, paid.` |
| Longer than `VARCHAR(n)` | `Value is longer than 255 characters.` |
| A column called `email` or `*_email` | `Invalid email format.` |
| JSON that does not parse | `Invalid JSON near line 3.` |
| A foreign key to a row that is not there | `No row in users has id 999.` |
| Unique or primary key held by another row | `A row with email "an@example.com" already exists.` |

The record itself never clashes with itself, and `NULL` never clashes. `S.validateRecord(table, values, { mode, rows, record, data })` returns them by column name.

## JSON

The record as an object, in the editor of `SqlEditor` (`language="json"`: keys `syn-type`, strings `syn-string`, numbers `syn-number`, `true` / `false` / `null` `syn-keyword`). A JSON column is written as the JSON it holds, not as a string. Above it **Format**, **Copy** and **Validate**.

- What is typed applies to the form while it is valid. A column left out keeps its value; a column that does not exist, or is generated, is not changed and a line says so (`Column "x" does not exist in users and is ignored.`).
- A syntax error marks its line (gutter and band in `removed`) and says it under the editor: `Invalid JSON near line 3.` with **Go to line**. The line is the one of the token where reading stops, found by `S.parseJson`, which reads JSON by hand so that every browser agrees. The Form and Related records tabs do not open while the text is broken.
- **Validate** checks the whole record like Create and Save do: an `Alert` "No problems" ("All 5 columns are valid.") or "2 problems" with a line for each column.

## Related records

Two groups, as in `TableRelationships`: **References** (the rows this record points at) and **Referenced by** (the rows that point at it). Each foreign key is one disclosure: `orders.user_id · 12 rows` (for References `orders.user_id → users.id · 1 row`). Opening one shows a small `DataGrid` (compact, no checkboxes, 50 rows at most with "50 of 312 rows") in the panel, one open at a time; one with no rows cannot be opened. It reads the saved record, not the draft.

## Using it with the grid

`DataGrid` has `openOnClick` for this: a click on a cell opens its row (⏎ and a double click do already). In Screen10 the menu of a row opens it too (View ⏎ as it is, Edit record F2 with the focus in the form, Duplicate ⌘D as a new record with the same values but not its counter), Add record ⌘⏎ opens a new one, and what is saved joins the working copy with an Undo toast and `modified` cells.
