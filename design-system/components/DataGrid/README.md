# DataGrid

The records of one table, as a grid. Not a `DataTable`: it is for reading and editing values cell by cell, so it is denser, scrolls both ways and keeps its headers and first column in view.

- Props: `columns` (a table's `Column[]`, each may carry `width`), `rows` (objects keyed by column name), `selected` (row indexes) with `onSelect(indexes)`, `activeCell` (`{row, column}`) with `onActiveCell(cell)`, `modified` (`{row, column}[]`), `onOpenRow(index)` (double click or ⏎; with `openOnClick`, a click on a cell too, for a grid that sits beside a `RecordEditor`), `onRowAction(action, row)`, `sort` (`{column, dir}`, to mark the header), `loading`, `empty` (`true` for the default message or any node), `density` (`regular` 28px rows, `compact` 24px), `selectable` (`false` leaves out the checkboxes: the gutter only numbers the rows, as in the grid of Related records) and `label`.
- **Header** (sticky): the key glyph (`pk` amber key, `fk` teal link), the column name in mono and its type in `ink-3`. The row-number gutter and the first column are sticky too; the grid scrolls sideways under them.
- **Gutter:** the row number in mono `ink-3`; on hover, or when the row is selected, a checkbox takes its place. The header's checkbox selects all rows.
- **Cells:** `NULL` is the `.ss-null` token (mono, `ink-3`), never an empty cell. Text is cut with an ellipsis and carries its full value as a title. Numbers are mono and right-aligned (a `DECIMAL(12,2)` always shows two decimals), timestamps (`TIMESTAMP`, `TIMESTAMPTZ`, `DATETIME`, `DATE`, `TIME`) are `YYYY-MM-DD HH:mm:ss`, booleans are `true` / `false`.
- **States:** hover `bg-4`; selected row `accent-subtle`; active cell a 2px `accent` outline; a modified cell `modified-subtle` (pair it with the Unsaved changes status of the toolbar). Arrow keys move the active cell, ⏎ opens the row, Space selects it, Esc clears the selection.
- **Sorted column:** with `sort` the header of that column ends in an arrow (`aria-sort` says the same) and is made wide enough for it. The grid never sorts by itself; the order is `DataToolbar`'s Sort.
- **Row menu:** with `onRowAction`, a right click on a row makes its cell the active one and opens a `ContextMenu` labelled `users · row 4`: **View** ⏎, **Edit record** F2, **Duplicate** ⌘D, **Copy as JSON** ⇧⌘C, then, after a separator, **Delete** ⌫ in `removed`. The menu and the keys call `onRowAction('view' | 'edit' | 'duplicate' | 'copy' | 'delete', row)`; the host decides what a row is when the row is one of several selected (Delete then acts on the selection). The menu closes on Esc, on a press outside, on scroll and on resize.
- **Deleting rows** always goes through a `ConfirmDialog` with a `danger` button that names the rows and the table, then states the consequence: `Delete 3 rows from "users"?` — "This removes 3 rows from `public.users` in the working copy." — and, for every foreign key that points at the table with rows behind it, an `Alert`: `warn` "7 rows in orders will be deleted too" (ON DELETE CASCADE) or "orders.user_id will be set to NULL in 2 rows" (SET NULL), `error` "2 rows in payments reference these rows" with "The delete will fail" (RESTRICT, NO ACTION). Once done, a toast offers Undo.
- `loading` shows 12 static skeleton rows, no animation. `empty` shows its message under the header: `true` is the default ("This table has no rows."), or pass an `EmptyState` with `compact`: "This table has no rows." with Add record and Import Records, "No rows match 2 filters." with Clear filters.
- **Invalid cells:** `invalid` (`{row, column, message}[]`) marks cells that will not be accepted, as in the preview of Import Records: `removed-subtle` fill, a 1px `removed` outline and an alert glyph after the value; the message is the cell's title. It is for values that are not in the table yet; a value that was edited is `modified`.
- Values are `null`, numbers, booleans or strings; the grid does not edit anything by itself.
