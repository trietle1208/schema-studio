# ImportRecordsDialog

Import Records: a CSV or JSON file, or pasted text, becomes rows of one table. A 960px `Modal` with a `Stepper` (**Source → Map columns → Settings → Review & import**), Cancel, Back and Next (⌘⏎) in the footer; the last step's button reads "Import 985 rows". The body keeps one height (708px, `height` to change it) so the dialog does not jump between steps. Nothing is written until the last button.

- Props: `table` (the destination; the `users` of the sample), `data` (the rows of every table: unique keys and foreign keys are checked against them), `schema` (the first part of `ecommerce.public.users`), `onImport({ table, insert, update, counts })` (rows were written: `insert` holds the values to add, `update` `{match, values}`; complete a new row with `completeRecord`), `onViewRows`, `onClose`, `height`. To start somewhere (a preview, a test): `step` (`source` | `map` | `settings` | `review`), `source` (`file` | `paste`), `file` (`{name}`) with its `text`, `mapping`, `settings`, `phase` (`importing` | `done`), `progress` (rows processed, freezes the bar), `fail` (`{line, message}`: the database refuses that row), `open` (review groups that are open), `duration` (seconds shown in the result).
- Esc closes, except while rows are being imported (then there is no close button either, only Cancel import). ⌘⏎ is the primary button of the step.

## 1 · Source
- **Destination** is read-only: `ecommerce.public.users` with "1,248 rows · 5 columns". **Upload file / Paste** is a `SegmentedControl`.
- Upload: a `DropZone` ("Drop CSV or JSON file here or click to browse", "CSV, JSON · up to 50 MB"). With a file it is the file row: the name in mono and "48 KB · CSV · UTF-8 · comma · 1,000 rows · header row", Replace, remove. A file over 50 MB says "File is larger than 50 MB." Paste: an editor with line numbers.
- What was found can be changed: **Delimiter** (comma, semicolon, tab, pipe) and **First row contains column names**; JSON (an array of objects) has neither. Under them the first 8 rows as the file has them.
- A text that cannot be read says so and names the line, in the footer and in an `Alert`: "Unable to parse JSON near line 3.", "Unable to parse CSV near line 42." Next waits for rows: "Parsed 1,000 rows · 4 columns".

## 2 · Map columns
- One row per column of the **destination**: the column of the file that fills it (a `Select`: **Ignore**, each file column, **Constant value…** which turns the sample into an input), a sample, an arrow, the destination (key glyph, name, `VARCHAR(255) · Unique · Required`) and badges. The dialog starts from `matchColumns`: the same name, a name that holds it (`full_name` → `name`), the one date column for the one date column (`signup_date` → `created_at`). "Not imported: country_code" names the file columns nobody uses; Reset mapping goes back.
- Badges: **Matched** (found by the dialog; the title says how), **Manual** (chosen), **Type conversion** (text becomes a number, a date a timestamp: `2024-01-01` → `2024-01-01 00:00:00`), **Skipped** (left out: NULL or the default), **Skipped (id generated)** (a serial column is never filled), **Required** in `removed` (nothing fills a column that cannot be NULL).
- An `Alert` says the first thing wrong: `Column "email" cannot be NULL.` — with no column for it, Next is off ("Choose a column of the file or give it a constant value."); with some rows lacking it, "2 rows have no value for email, the first on line 5." and the rest are counted.
- **Preview** is a compact `DataGrid` of the first 10 rows after conversion; a cell that will not go in is marked (`invalid`: `removed` outline, an alert glyph, the reason as its title).

## 3 · Settings
- **When a row already exists:** **Insert only** (default: a row whose unique key exists is a warning and is left out), **Upsert on email** (updates the row with the same key; its box names the key and lists what it **Overwrites**: `name`, `created_at`; needs a unique column the file fills), **Skip duplicates** (left out without a warning).
- **Options:** Treat empty cells as NULL (a required column with a default takes the default), Skip invalid rows (off: the import does not run while a row is invalid), Check foreign keys (off and disabled for a table with none: "users has no foreign keys."), Stop on first error (always on in a transaction), Run in one transaction ("If a row fails, nothing is written.").
- The **Summary** follows every change: `1,000 rows · 985 valid · 10 warnings · 5 errors` (Upsert: `995 valid · 0 warnings`; Skip duplicates adds `10 skipped`), and says what will happen to the rows.

## 4 · Review & import
- Four numbers (rows, will be imported, warnings, errors), the settings in one line with Edit settings, then the problems **by kind**, each a group that opens and closes: **Missing required values**, **Duplicate keys**, **Invalid types**, **Foreign keys**, **Invalid dates**. A group shows its number of rows, what to do about it and the first 5 (`Line 5 · email · NULL · Column "email" cannot be NULL.`) with "+ 5 more in the error report."; a kind with no problem is a green check and a line saying so. Errors are `removed`, duplicates `modified` (when they are only left out, `accent`).
- **Import 985 rows** → progress (`Progress`, "620 of 1,000 rows", Processed / Inserted / Skipped / Failed) and Cancel import → **Import completed** ("985 rows were added to ecommerce.public.users in 1.2 s."; the numbers; the skipped rows by reason; "Not saved yet. Press ⌘Z to remove 985 rows again.") with **View imported rows**, **Download error report** (a CSV of `line,column,value,reason`), **Import another file**, **Close**.
- A row the database refuses: in one transaction "Import failed — Nothing was written." with the line and the message; without one the rows that went through stay (and the import stops there if Stop on first error is on). Cancelling in a transaction undoes everything, otherwise "412 rows were already added."

## What is checked
What the database would refuse, row by row, after conversion: NOT NULL, the type and length (`Value must be a number.`, `Value is longer than 255 characters.`), dates (`Invalid timestamp format.`), unique keys against the table and against earlier rows of the file (`A row with email "x" already exists.`), foreign keys (`No row in users has id 999.`). The wording is that of `RecordEditor`. A row with a problem is an **error**; a duplicate that Insert only cannot take is a **warning**. Both are left out when Skip invalid rows is on.

Helpers on `window.SchemaStudio` for the port and its tests: `parseCsv`, `readRecordsFile`, `matchColumns`, `analyzeImport`, `runImport`, `importReport`, `importSummary`; `sample.csv` is `users_import.csv` (1,000 rows made the same way every time: 5 errors, 10 emails that already belong to a user).
