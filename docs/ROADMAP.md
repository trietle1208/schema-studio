# Roadmap

Each step is sized for one Claude Code session. Tick it off when `npm run build` and `npm test` pass.

## Phase 1 — Foundation
- [x] **1.1 Scaffold**: Vite + React + TS, ESLint, Vitest, folder layout from CLAUDE.md. Import `tokens.css` + `bundle.css`, copy fonts. Show an empty `AppShell` with `Sidebar`.
- [x] **1.2 Primitives**: port Icon, Logo, Button, IconButton, Badge, Kbd, Avatar, Input, Field, Select, Checkbox, Radio, Switch, SegmentedControl to `.tsx`.
- [x] **1.3 Model**: `src/core/model.ts` from `index.d.ts`; `validate.ts` (column/table name rules) with tests.

## Phase 2 — Workspace
- [x] **2.1 Store**: Zustand schema store (tables, positions, selection, dirty flag) + undo/redo (zundo). Load the ecommerce sample.
- [x] **2.2 Canvas**: port TableNode + ERCanvas (drag, pan, zoom, edges, minimap, legend, context menu).
- [x] **2.3 Inspector**: port Inspector, TypeSelect, ColumnEditor; edits go through the store.
- [x] **2.4 Toolbar + StatusBar**: save state, undo/redo, zoom, search, shortcuts (⌘S/⌘Z/⌘K/F2/⌫/Esc).
- [x] **2.5 Dialogs**: Modal, ConfirmDialog (delete table), Toast.

## Phase 3 — Persistence & list
- [x] **3.1 Dexie**: schemas + versions tables; save creates a new immutable version snapshot.
- [x] **3.2 Schema list screen**: DataTable with search, engine filter, sort; New Schema; Empty state.
- [x] **3.2a New table**: "New table" in the canvas menu (right-click) and in the inspector; the table is selected and its name put into rename mode.
- [x] **3.2b Delete schema**: row menu and ⌫ in the schema list, confirmed in a dialog; removes the schema with all its versions.
- [x] **3.3 Routing**: list ↔ workspace ↔ history ↔ diff (react-router or simple state router).

## Phase 4 — Import / Export (MVP done here)
- [x] **4.1 Parser**: PostgreSQL `CREATE TABLE / ALTER TABLE ADD CONSTRAINT / CREATE INDEX` → model; errors with line numbers. Tests with good and broken fixtures.
- [x] **4.2 Import dialog**: DropZone, SqlEditor, live ParseStatus summary, auto-layout new tables in a grid.
- [x] **4.3 SQL generator**: model → PostgreSQL DDL with options (indexes, FKs, comments, DROP IF EXISTS). Round-trip test: parse(generate(x)) == x.
- [x] **4.4 Export dialog**: SQL / JSON, preview, download file.

## Phase 5 — Versions
- [x] **5.1 Diff engine**: compare two snapshots → DiffGroup[] (tables, columns, indexes, relationships). Tests.
- [x] **5.2 Version history screen**.
- [x] **5.3 Schema diff screen** (side-by-side DdlDiff).
- [x] **5.4 Migration generator**: diff → ALTER statements in a transaction; flag destructive changes.

## Phase 6 — Later
- [x] **MySQL dialect: parser**: `CREATE TABLE / ALTER TABLE / CREATE INDEX` as mysqldump, phpMyAdmin and hand-written DDL have them → model; Import dialog offers MySQL. Tests with dump fixtures.
- [x] **MySQL dialect: generator**: model → MySQL DDL and migrations (no transaction: MySQL commits each statement); exporting for the other engine converts the data types; the type picker offers MySQL's types in a MySQL schema. Tests, and checked against MySQL 8.
- [x] **Light/dark toggle in Settings**: a Settings dialog (sidebar, ⌘,) with the theme; kept in the browser and applied before the first paint.
- [ ] Desktop app with Tauri (open/save `.sql` files on disk)
- [x] **Infer missing relationships**: a database that declares no foreign keys gets them from the names of its columns (`orders.user_id` → `users.id`), on import and from the canvas menu. They are marked `inferred`: drawn dashed, and left out of DDL, migrations and the diff until they are made foreign keys in the column editor or included in an export. Tests with a dump that has no foreign keys.
- [x] **Connect to a live database (read-only introspection)**: the Connect to database tab of Import Schema reads the tables of a PostgreSQL or MySQL database through a local bridge (`npm run bridge`) in a read-only transaction; the catalog becomes DDL and is imported like a script. Tests with catalogs of real databases.
- [x] **Languages (English, Vietnamese)**: every word of the app is a message of `src/core/i18n`: `en.ts` names each one, with its placeholders and, where a number changes it, its plural forms, and `vi.ts` has the Vietnamese for all of them; a key that does not exist, or a placeholder that is left out, does not type-check. `t()` gives a message in the language of the app, in components, in the actions that show toasts and in the core (validation, the errors and warnings of the parsers, relative times, what a version changed, the summary of a diff). Language in Settings switches at once, is kept in the browser like the theme, and is the `lang` of the page. Exported SQL, JSON and migrations, with the comments in them, stay in English; a destructive change is said in the app's language in the dialog and in English in the script. Tests: both dictionaries have the same messages, placeholders and backticks, and the core answers in Vietnamese.
- [x] **Arrange tables**: "Arrange tables" in the toolbar and the canvas menu moves every table to where its relationships put it, in one undo step: each group of related tables in columns, referenced tables left of the tables that reference them (on both sides of a master table with many), the tables without a relationship in a grid beside or under them. An import is arranged the same way instead of in a plain grid. Tests with the sample and the dumps.

## Phase 7 — Working with the diagram
Planned on 2026-10-08, after Arrange tables. In the order they are to be done.
- [x] **7.1 Review inferred relationships**: a dialog that lists every inferred foreign key (`orders.user_id → users.id`) with Accept (it becomes a declared foreign key) and Remove for each, and Accept all / Remove all. Opened from the canvas menu, the inspector and the toast of Infer relationships. Each decision is one undo step.
- [x] **7.2 Table menu actions**: the items of the table menu that did nothing: Add column (⌘⏎, now from anywhere in the workspace), Add foreign key… (a dialog, also behind the inspector's button: an existing column or a new one named after the referenced table, the table it references, ON DELETE; it opens on what the column names point to), Copy CREATE TABLE (⇧⌘C: the table with its indexes and foreign keys, in the schema's dialect), Focus related tables (the canvas shows only the table and the tables one foreign key away, fitted, until Show all tables or Esc). Esc on an open menu closes only the menu.
- [x] **7.3 Missing shortcuts**: the ones the buttons already name: ⇧1 fit, ⌘+ / ⌘− / ⌘0 zoom (⌘= and the number pad too), ⌘H history, ⌘D duplicate; and ⇧A for Arrange tables, named on its button and in the canvas menu. In the workspace the browser's own ⌘D, ⌘H and zoom keys are off, under a dialog too. ⇧1 and ⇧A type their character in a field; ⌘D and ⌘H first leave a table name or a type that is being edited, which keeps it.
- [x] **7.4 Draw a foreign key**: drag from a column of one table to a column of another to reference it. The line follows the pointer and ends on the column once that is one it can end on: a primary key or a unique column of another table. The hint of the canvas names the foreign key or says why not, and Esc gives it up. Letting go declares it in one undo step and selects the column; a column that referenced another column references this one in its place, with its ON DELETE.
- [x] **7.5 Select several tables**: Shift + click on a table adds it to the selected tables or takes it out, and a frame dragged over the empty canvas with Shift held adds the tables it touches (Esc gives the frame up). Dragging one of the selected tables moves them all, as they stand to each other, in one undo step. Arrange tables (⇧A, the toolbar, the canvas menu) then arranges only them, among themselves and from the top left corner of where they were: the other tables and the view stay. With several selected the inspector says how many, and the keys that are for one table (F2, ⌘⏎, ⌘D, ⇧⌘C, ⌫) do nothing.
- [x] **7.6 Minimap navigation**: a press on the minimap puts the middle of the view there, and goes on as a drag; the visible area is dragged by where it is taken hold of, without a jump. While it is dragged the minimap is not scaled again, so the visible area follows the pointer; it fits everything again when the drag ends. A press on the minimap leaves the selected tables selected.
- [x] **7.7 Table groups**: a colour and a label for the tables of one module, suggested from the prefix of their names (`da_chung_tu*`). "Table groups…" in the canvas menu and the inspector opens a dialog that lists the groups (label, one of seven colours, remove; New group) and under them the ones the names point to: tables that begin with the same words, named after the table the others are called after, past what every table begins with (`da_`). Add group and Add all suggested make them. A table of a group has a bar of the colour on its head and in the minimap, and the canvas lists the groups over the legend, where a press selects the tables of one. The Group field of the inspector (Table settings, and for several selected tables) moves tables between groups or makes a new one of them. Groups are of the diagram: saved with a version and undone like any edit, and left out of DDL, migrations and the diff. A renamed or duplicated table stays in its group. Tests with the sample and the dumps.
- [x] **7.8 Lines around tables**: relationship lines are routed through the gaps instead of behind the tables between their two ends; Arrange tables leaves room for them. A line whose curve would run behind a table goes around instead: out of the side of each end, then along horizontal and vertical lines with rounded corners, the shortest way with few corners that keeps clear of every table. Lines to different columns keep different distances, so two of them in one gap do not run as one. A line that has nothing in its way stays the curve it was, and one that has no way around (a table right against its end) too. Arrange tables gives a line between tables more than a column apart a gap in each column it passes through. Tests with the sample and the dumps.
- [x] **7.9 Export the diagram**: PNG and SVG in the Export dialog. Both are the whole diagram as the canvas draws it (tables, columns, relationship lines, group colours), in the dark or the light theme, with or without the background. An SVG can carry Geist Mono with it; a PNG is drawn at 1×, 2× or 3×, less for a diagram too large for a browser to draw. The dialog previews the picture; Copy puts the SVG text or the PNG image on the clipboard. Tests with the sample and a dump.
- [x] **7.10 Choose the tables of a group**: "Choose tables" on a group of the Table groups dialog lists the tables of the schema under it, each to be ticked into the group or out of it, one undo step a tick. A table of another group says which, and a tick moves it. A filter leaves the tables whose names hold every word of it, and the button beside it adds the ones shown that are in no group, or once there are none removes the ones shown from the group. New group opens on its tables, and a group keeps its row when it is renamed, so a label can be typed and a table ticked in one go. Tests with the sample and a dump.
- [x] **7.11 Resize the sidebar and the inspector**: the line between a panel and the canvas is a handle (`ResizeHandle`): dragged, it makes the sidebar 200 to 440px wide and the inspector 320 to 720px, and never leaves the canvas less than 400px of the window. A double click gives the panel the width it has by itself. With the keyboard the handle is a separator: the arrows move it 16px, Home and End to its limits. The widths are of this browser, kept like the theme, and are the `--w-sidebar` and `--w-inspector` tokens of the page. Tests.
- [x] **7.12 Resize tables**: a table on the canvas has a handle at either side. Dragged, it makes the table 160 to 640px wide in steps of 4px, in one undo step; the left side lands on the grid and the right side stays where it is. A double click fits the table to its text: its name and the name and type of its widest column. With several tables selected a drag of one makes them all as wide, and a double click fits each. The width is of the diagram, kept with the position: saved with a version, kept by a move, a rename and a copy, and marked as an unsaved change. Relationship lines end at the sides of the table as wide as it is, Arrange tables makes a column as wide as its widest table, and the exported PNG and SVG draw each table at its width with the text that fits it. Tests with the sample and a dump.
